# 70. Climbing Stairs

| Topic | Difficulty | Pattern |
| ----- | ---------- | ------- |
| Dynamic Programming | Easy | 1D DP — Linear DP |

---

# 📌 Problem Description

You are climbing a staircase with `n` steps.

At every move, you can climb either:

```text
1 step
OR
2 steps
```

Find the **number of distinct ways** to reach the top.

The order of the steps matters.

---

# Example

### Example 1

Input

```text
n = 2
```

Output

```text
2
```

Ways:

```text
1 + 1
2
```

---

### Example 2

Input

```text
n = 3
```

Output

```text
3
```

Ways:

```text
1 + 1 + 1
1 + 2
2 + 1
```

---

# 🧠 Intuition

Think about the **last move** used to reach step `n`.

There are only two possibilities.

### Case 1 — Last move is 1 step

We must have been at:

```text
n - 1
 ↓
 n
```

So the number of ways is:

```text
dp[n-1]
```

---

### Case 2 — Last move is 2 steps

We must have been at:

```text
n - 2
 ↓
   n
```

So the number of ways is:

```text
dp[n-2]
```

---

Therefore:

```text
ways to reach n

=

ways to reach n-1

+

ways to reach n-2
```

---

# Key Observation

Define:

```text
dp[i] = number of distinct ways to reach step i
```

Therefore:

```text
dp[i] = dp[i-1] + dp[i-2]
```

Base cases:

```text
dp[1] = 1
dp[2] = 2
```

For example:

```text
dp[1] = 1

dp[2] = 2

dp[3] = 3

dp[4] = 5

dp[5] = 8
```

This is the same recurrence structure as Fibonacci.

---

# Algorithm

```text
Create DP array

↓

dp[1] = 1
dp[2] = 2

↓

For i = 3 to n

    dp[i] = dp[i-1] + dp[i-2]

↓

Return dp[n]
```

---

# Code — Tabulation

```cpp
class Solution {
public:

    int climbStairs(int n)
    {
        if(n <= 2)
            return n;

        vector<int> dp(n + 1, 0);

        dp[1] = 1;
        dp[2] = 2;

        for(int i = 3; i <= n; i++)
        {
            dp[i] = dp[i-1] + dp[i-2];
        }

        return dp[n];
    }
};
```

---

# Complexity — Tabulation

| Complexity | Value |
|------------|-------|
| Time | **O(n)** |
| Space | **O(n)** |

### Time

We calculate every state once:

```text
dp[1]
dp[2]
...
dp[n]
```

Therefore:

```text
O(n)
```

### Space

We store all `n` states:

```text
dp[0 ... n]
```

Therefore:

```text
O(n)
```

---

# Space Optimization

Look at the transition:

```text
dp[i] = dp[i-1] + dp[i-2]
```

To calculate `dp[i]`, we only need:

```text
dp[i-1]
dp[i-2]
```

We do **not** need the entire DP array.

So instead of:

```text
dp[0]
dp[1]
dp[2]
dp[3]
...
dp[n]
```

we only maintain two variables.

---

# Variable Meaning

Initially:

```text
first  = dp[1]
second = dp[2]
```

For every iteration:

```text
ans = first + second
```

Then shift:

```text
first = second
second = ans
```

So after the shift:

```text
first  = dp[i-1]
second = dp[i]
```

---

# Code — Space Optimized

```cpp
class Solution {
public:

    int climbStairs(int n)
    {
        if(n <= 2)
            return n;

        int first = 1;
        int second = 2;

        for(int i = 3; i <= n; i++)
        {
            int ans = first + second;

            first = second;
            second = ans;
        }

        return second;
    }
};
```

# Complexity — Space Optimized

| Complexity | Value |
|------------|-------|
| Time | **O(n)** |
| Space | **O(1)** |

### Time

We still calculate every state once:

```text
O(n)
```

### Space

Only two variables are maintained:

```text
first
second
```

Therefore:

```text
O(1)
```

# Comparison

| Approach | Time | Space |
| -------- | ---- | ----- |
| Recursion | O(2^n) | O(n) |

| Tabulation | O(n) | O(n) |

# Recognition Pattern

When you see:

```text
Current position
+
Multiple ways to reach it
+
Choices depend on previous positions
+
Overlapping subproblems
```

```text
1D DP
```

# Key Takeaways

- `dp[i]` represents the number of ways to reach step `i`.
- To reach `i`, the last move can be either `1` or `2`.
- Therefore the current state depends on `i-1` and `i-2`.
- Tabulation stores every state.
- Space optimization keeps only the last two states.
- Tabulation uses **O(n)** space.
- Space-optimized DP uses **O(1)** space.
- The important pattern is not memorizing the Fibonacci-like formula.
- The important reasoning is:

```text
What was my last choice?

        ↓

What smaller states could lead here?

        ↓

Combine those states.
```
