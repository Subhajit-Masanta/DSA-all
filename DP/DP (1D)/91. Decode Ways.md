# 91. Decode Ways

| Topic | Difficulty | Pattern |
| ----- | ---------- | ------- |
| Dynamic Programming | Medium | 1D DP — Counting Ways |

---

# 📌 Problem Description

You are given a string `s` containing digits.

The digits are encoded using:

```text
1  → A
2  → B
...
25 → Y
26 → Z
```

Find the **number of different ways** to decode the entire string.

A decoding can use:

```text
1 digit
OR
2 digits
```

but the selected number must represent a valid code from:

```text
1 to 26
```

---



```text
2 ways
```


# 🧠 Intuition

This problem is very similar to:

```text
Climbing Stairs
```

In Climbing Stairs:

```text
Take 1 step
OR
Take 2 steps
```

Here:

```text
Take 1 digit
OR
Take 2 digits
```

The difference is that the choices are **not always valid**.

---

# Key Observation

Define:

```text
dp[i] = number of ways to decode the first i characters
```

For example:

```text
s = "226"
```

Then:

```text
dp[0] → ""
dp[1] → "2"
dp[2] → "22"
dp[3] → "226"
```

---

# Why dp[0] = 1?

`dp[0]` represents the empty string.

There is exactly **one way** to decode an empty string:

```text
Do nothing
```

So:

```text
dp[0] = 1
```

This is important because it allows valid first characters or pairs to build the answer.

---

# Choices

At every position, there are two possible choices.

## Choice 1 — Take One Digit

The current digit is:

```text
s[i-1]
```

A single digit is valid only when:

```text
'1' to '9'
```

Therefore:

```text
'0' → invalid
'1'...'9' → valid
```

If valid:

```text
dp[i] += dp[i-1]
```

---

## Choice 2 — Take Two Digits

Take:

```text
s[i-2]s[i-1]
```

The number must be between:

```text
10 and 26
```

For example:

```text
10 → valid
11 → valid
20 → valid
26 → valid
27 → invalid
06 → invalid
30 → invalid
```

If valid:

```text
dp[i] += dp[i-2]
```

---

# Important Zero Rule

`0` cannot be decoded by itself.

Therefore:

```text
"0"  → invalid
"06" → invalid
"01" → invalid
```

But:

```text
"10" → valid
"20" → valid
```

because `10` and `20` are valid two-digit codes.

---

# Algorithm

```text
Create dp array of size n + 1

↓

dp[0] = 1

↓

For i = 1 to n:

    Check current digit

    If current digit is not '0':

        dp[i] += dp[i-1]

    Check previous + current digit

    If two-digit number is between 10 and 26:

        dp[i] += dp[i-2]

↓

Return dp[n]
```

---

# Code — Tabulation

```cpp
class Solution {
public:

    int numDecodings(string s)
    {
        int n = s.size();

        if(s[0] == '0')
            return 0;

        vector<int> dp(n + 1, 0);

        dp[0] = 1;

        for(int i = 1; i <= n; i++)
        {
            // Take one digit
            if(s[i-1] != '0')
            {
                dp[i] += dp[i-1];
            }

            // Take two digits
            if(i >= 2)
            {
                int num =
                    (s[i-2] - '0') * 10 +
                    (s[i-1] - '0');

                if(num >= 10 && num <= 26)
                {
                    dp[i] += dp[i-2];
                }
            }
        }

        return dp[n];
    }
};
```

# Why We Don't Need an Unordered Map

The mapping:

```text
1 → A
2 → B
...
26 → Z
```

does not need to be stored.

We only care whether a number is valid.

Therefore we only check:

### One digit

```text
'1' <= digit <= '9'
```

### Two digits

```text
10 <= number <= 26
```

The actual letters are irrelevant.

---

# Complexity

| Complexity | Value |
|------------|-------|
| Time | **O(n)** |
| Space | **O(n)** |

### Time

Every character is processed once.

```text
O(n)
```

### Space

The DP array contains:

```text
n + 1
```

states.

Therefore:

```text
O(n)
```

---

# Space Optimization

Each state only depends on:

```text
dp[i-1]
dp[i-2]
```

So theoretically the DP can be reduced to:

```text
O(1)
```

space.

However, the full DP array is often easier to understand and debug for this problem, especially while learning the pattern.

---

# DP Pattern Learned

```text
1D DP — Counting Ways
```

State:

```text
dp[i] = number of ways to decode
        the first i characters
```

Transitions:

```text
Valid one digit
        ↓
dp[i-1]
```

```text
Valid two digits
        ↓
dp[i-2]
```

Since we are **counting ways**, we add valid choices:

```text
dp[i] =
    validOneDigit ? dp[i-1] : 0

    +

    validTwoDigits ? dp[i-2] : 0
```

---

# Recognition Pattern

When you see:

```text
String / sequence
+
Can take 1 element or 2 elements
+
Need to count valid ways
+
Choices overlap
```

Think:

```text
1D DP
```

Then ask:

```text
1. What does dp[i] represent?

2. Can I take one element?

3. Can I take two elements?

4. Is each choice valid?

5. If valid, which previous state does it depend on?

6. Since I am counting, do I ADD the valid choices?
```

---

# Connection With Previous Problems

### Climbing Stairs

```text
dp[i] = dp[i-1] + dp[i-2]
```

Both choices are always valid.

---

### Decode Ways

```text
Valid 1-digit choice
        +
Valid 2-digit choice
```

Only valid choices contribute.

So conceptually:

```text
Climbing Stairs
       ↓
Same 1-step / 2-step structure
       ↓
Decode Ways
       ↓
Add extra validity rules
```

# Key Takeaways

- Decode Ways is a **1D DP counting problem**.
- It is similar to Climbing Stairs.
- At every position, try:
  - one digit
  - two digits
- A single `0` is invalid.
- Two digits are valid only when they form a number from `10` to `26`.
- `dp[0] = 1` represents one way to decode an empty prefix.
- We count ways, so valid choices are **added**.
- We do not need an `unordered_map`.
- The important state is:

```text
dp[i] = number of ways to decode the first i characters
```

The core pattern is:

```text
                position i
                    |
            ┌───────┴───────┐
            ↓               ↓
       Take 1 digit     Take 2 digits
            |               |
          valid?           valid?
            |               |
         dp[i-1]          dp[i-2]
            \               /
             \             /
                ADD
                 ↓
               dp[i]
```
