# 713. Subarray Product Less Than K

| Topic | Difficulty | Pattern |
| :--- | :--- | :--- |
| Arrays | Medium | Variable Sliding Window (Counting) |

---

## 📌 Problem Description
Given an array of **positive** integers `nums` and an integer `k`, return the number of **contiguous subarrays** where the product of all the elements in the subarray is strictly less than `k`.

---

## 🧠 Core Insight: The Monotonic Property
Because all numbers in the array are **strictly positive** (1 or greater):
- **Expanding** the window (multiplying) strictly **increases** or maintains the product.
- **Shrinking** the window (dividing) strictly **decreases** or maintains the product.

This predictable behavior guarantees a Variable Sliding Window will work.

---

## 🪟 The Algorithm & The Math

1.  **Expand:** Multiply the `product` by `nums[right]`.
2.  **Shrink:** `while` the $product \ge k$, divide it by `nums[left]` and increment `left`.
3.  **Count:** Once the window is valid, how many new valid subarrays did we just create by adding `nums[right]`?
    * The number of new subarrays ending at `right` is exactly the length of the window: `right - left + 1`.



**Mathematical Proof of the Count:**
If the valid window is `[5, 2, 6]` (indices $0$ to $2$):
Valid subarrays ending at `6`:
1. `[6]`
2. `[2, 6]`
3. `[5, 2, 6]`
Total = $3$. Which equals $2 - 0 + 1 = 3$.

---

## ⚠️ The Critical Edge Case
If $k \le 1$, the answer is **always 0**.
Why? The array contains strictly positive integers ($x \ge 1$). The smallest possible product is $1$. If $k$ is $1$ (or $0$), it is impossible for any product to be *strictly less* than $k$. 
**You must catch this before the loop, or your code will infinite loop or divide by zero.**

---

## 🧪 Example Walkthrough
**Input:** `nums = [10, 5, 2, 6]`, `k = 100`

- `right = 0`: `[10]`. Product = $10$. Valid. Count += $1$. (Total: $1$)
- `right = 1`: `[10, 5]`. Product = $50$. Valid. Count += $2$. (Total: $3$)
- `right = 2`: `[10, 5, 2]`. Product = $100$. **Invalid!**
  - Shrink: Divide by $10$, move `left` to $1$. Product = $10$. Valid.
  - Window is now `[5, 2]`. Count += $2$. (Total: $5$)
- `right = 3`: `[5, 2, 6]`. Product = $60$. Valid. Count += $3$. (Total: $8$)

**Final Answer:** `8`

---

## ⏱ Time & Space Complexity
- **Time Complexity:** $O(n)$ — Every element is multiplied once and divided at most once. Both pointers only move forward.
- **Space Complexity:** $O(1)$ — Only simple integer variables are used.

---

## ⚠️ Common Mistakes to Avoid
- **Forgetting the Edge Case:** Not handling $k \le 1$ explicitly.
- **Using Prefix Sums:** Trying to convert this to an addition problem (unless you use logarithms, which introduces floating-point precision errors and is a terrible idea here).
- **The `if` Trap:** Using `if (product >= k)` instead of `while`. You must shrink the window until it is completely valid before counting.

---

## 🎯 Interview One-Liner
Maintain a variable sliding window for the product, shrinking from the left until strictly less than $k$, and at each step, add the current window size (`right - left + 1`) to your total count.

---

## 💻 Implementation (C++)

```cpp
class Solution {
public:
    int numSubarrayProductLessThanK(vector<int>& nums, int k) {
        // Critical edge case: product of positive integers cannot be < 1
        if (k <= 1) return 0;

        int left = 0;
        long long product = 1; // Prevent overflow on large inputs
        int count = 0;

        for (int right = 0; right < nums.size(); right++) {
            product *= nums[right];

            // Shrink until valid
            while (product >= k) {
                product /= nums[left];
                left++;
            }

            // Count all valid subarrays ending at 'right'
            count += right - left + 1;
        }

        return count;
    }
};
