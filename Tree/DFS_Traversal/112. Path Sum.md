# 112. Path Sum

| Topic | Difficulty | Pattern                            |
| ----- | ---------- | ---------------------------------- |
| Tree  | Easy       | DFS / Root-to-Leaf / State Passing |

---

## 📌 Problem Description

Given the root of a binary tree and an integer `targetSum`, determine whether there exists a **root-to-leaf** path whose node values add up to `targetSum`.

> A valid path **must start at the root and end at a leaf node**.

---

## 🧠 Intuition

Unlike previous tree problems where recursion returned information **upward** (height, boolean, diameter), this problem **passes information downward**.

At every node:

```text
Current Sum += Current Node Value
```

When we reach a **leaf node**, we check whether the accumulated sum equals `targetSum`.

---

## 🎯 Pattern Recognition

Keywords:

* DFS
* Root-to-Leaf
* State Passing
* Path Sum
* Tree Traversal

---

## ⚙️ Approach

For every node:

1. If node is `NULL`, return `false`.
2. Add current node value to the running sum.
3. If current node is a **leaf**:

   * Check whether `curr == targetSum`.
4. Otherwise recursively search:

   * Left subtree
   * Right subtree
5. Return:

```cpp
left || right
```

If either path is valid, return `true`.

## 🧪 Dry Run

Tree

```text
        5
      /   \
     4     8
    /
   11
  /  \
 7    2
```

Target Sum = **22**

Start

```text
curr = 0
```

Visit 5

```text

```

Visit 4

```text
curr = 9
```

Visit 11

```text
curr = 20
```

Visit 7

```text
curr = 27

Leaf

27 ≠ 22
```

Backtrack.

Visit 2

```text
curr = 22

Leaf

22 == 22

↓

Return true
```

## ⚠️ Common Mistakes

### 1. Checking Sum Before Reaching a Leaf

Wrong:

```cpp
if(curr == targetSum)
    return true;
```

Correct:

```cpp
if(root->left == nullptr &&
   root->right == nullptr &&
   curr == targetSum)
    return true;
```

---

### 2. Forgetting the NULL Base Case

Always check:

```cpp
if(root == nullptr)
    return false;
```

before accessing `root->val`.

---

### 3. Pruning Using

```cpp
curr > targetSum
```

Wrong.

Tree values can be **negative**, so a larger sum may decrease later.

---

## 🎯 Key Takeaways

* First tree problem using **state passing**.
* Sum is carried **downward**, not returned upward.
* Check the sum **only at leaf nodes**.
* Return `left || right` because only one valid path is needed.

---

## 💻 Implementation (C++)

```cpp
class Solution {
public:

    bool solve(TreeNode* root, int targetSum, int curr){

        if(root == nullptr)
            return false;

        curr += root->val;

        if(root->left == nullptr &&
           root->right == nullptr &&
           curr == targetSum)
            return true;

        return solve(root->left, targetSum, curr) ||
               solve(root->right, targetSum, curr);
    }

    bool hasPathSum(TreeNode* root, int targetSum) {

        if(root == nullptr)
            return false;

        return solve(root, targetSum, 0);
    }
};
```

---

## 💡 Alternative Interview Approach

Instead of carrying the **current sum**, many interview solutions carry the **remaining target**.

At every node:

```cpp
targetSum -= root->val;
```

At a leaf:

```cpp
return targetSum == root->val;
```

or equivalently after subtraction:

```cpp
return targetSum == 0;
```

Both approaches have the same time and space complexity.
