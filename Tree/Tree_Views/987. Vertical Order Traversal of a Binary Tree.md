# 987. Vertical Order Traversal of a Binary Tree

| Topic | Difficulty | Pattern                            |
| ----- | ---------- | ---------------------------------- |
| Tree  | Hard       | DFS/BFS + Coordinates + Nested Map |

---

## 📌 Problem Description

Given the root of a binary tree, return its **Vertical Order Traversal**.

Every node has a coordinate:

* Root → `(0,0)`
* Left Child → `(row+1, col-1)`
* Right Child → `(row+1, col+1)`

Rules:

1. Smaller column first.
2. Inside a column, smaller row first.
3. If multiple nodes have the **same row and same column**, sort by node value.

---

## 🧠 Intuition

Unlike previous BFS problems, we no longer care only about **levels**.

Every node now has **two coordinates**:

* Row (Depth)
* Column (Horizontal Distance)

The goal is to group nodes by **column** while preserving the required ordering.

Keywords:

* Vertical Traversal

## ⚙️ Approach

Perform DFS.

For every node:

* Store

```cpp
(column, row, value)
```

using

```cpp
map<int, map<int, multiset<int>>> mp;
```

Insert:

```cpp
mp[column][row].insert(root->val);
```

After DFS:

* Traverse columns from left to right.
* Traverse rows from top to bottom.
* Traverse multiset (already sorted).
* Build the final answer.

## ⚠️ Common Mistakes

### 1. Using unordered_map

Wrong.

Columns must remain sorted.

Use

```cpp
map
```

instead.

---

### 2. Using vector instead of multiset

If two nodes have the same:

* Row
* Column

they must be sorted by value.

`multiset` does this automatically.

---

### 3. Forgetting to Build the Answer

After DFS, iterate:

```text
Column

↓

Row

↓

Values

↓

Answer
```

---

## 🎯 Key Takeaways

* First Tree problem using coordinates.
* Store nodes by `(Column, Row)`.
* `map` keeps columns and rows sorted.
* `multiset` keeps values sorted.
* Vertical Traversal is the base for Top View and Bottom View.

---

## 💻 Implementation (DFS)

```cpp
class Solution {
public:

    map<int, map<int, multiset<int>>> mp;

    void solve(TreeNode* root, int row, int col){

        if(root == nullptr)
            return;

        mp[col][row].insert(root->val);

        solve(root->left, row + 1, col - 1);
        solve(root->right, row + 1, col + 1);
    }

    vector<vector<int>> verticalTraversal(TreeNode* root) {

        vector<vector<int>> ans;

        solve(root, 0, 0);

        for(auto col : mp){

            vector<int> curr;

            for(auto row : col.second){

                for(auto val : row.second)
                    curr.push_back(val);
            }

            ans.push_back(curr);
        }

        return ans;
    }
};
```

# 🔄 BFS Solution (Recommended for Understanding Coordinates)

## Why BFS?

BFS naturally processes nodes **level by level**.

Instead of passing `(row, column)` recursively like DFS, we store this information inside the queue.

Each queue element contains:

```cpp
(Node*, (column, row))
```

or

```cpp
queue<pair<TreeNode*, pair<int,int>>>
```

where

* First integer = Column (Horizontal Distance)
* Second integer = Row (Depth)

This allows us to know the exact position of every node while traversing level by level.

---

## Algorithm

1. Create

```cpp
map<int, map<int, multiset<int>>> mp;
```

2. Push

```cpp
(root, {0,0})
```

into the queue.

3. While queue is not empty

* Pop current node.
* Insert

```cpp
mp[column][row].insert(node->val);
```

* Push left child

```text
column - 1
row + 1
```

* Push right child

```text
column + 1
row + 1
```

4. Traverse the map and build the answer.

---

## BFS Code

```cpp
class Solution {
public:

    vector<vector<int>> verticalTraversal(TreeNode* root) {

        vector<vector<int>> ans;

        if(root == nullptr)
            return ans;

        map<int, map<int, multiset<int>>> mp;

        queue<pair<TreeNode*, pair<int,int>>> q;

        q.push({root,{0,0}});

        while(!q.empty()){

            auto t = q.front();
            q.pop();

            TreeNode* node = t.first;

            int column = t.second.first;
            int row = t.second.second;

            mp[column][row].insert(node->val);

            if(node->left)
                q.push({node->left,{column-1,row+1}});

            if(node->right)
                q.push({node->right,{column+1,row+1}});
        }

        for(auto col : mp){

            vector<int> curr;

            for(auto row : col.second){

                for(auto val : row.second){

                    curr.push_back(val);

                }
            }

            ans.push_back(curr);
        }

        return ans;
    }
};
```

# DFS vs BFS

| Feature                | DFS                 | BFS                   |
| ---------------------- | ------------------- | --------------------- |
| Position Storage       | Function Parameters | Queue                 |
| Stores                 | `(row, column)`     | `(node, row, column)` |
| Recursion              | ✅                   | ❌                     |
| Queue                  | ❌                   | ✅                     |
| Coordinates Calculated | During recursion    | During traversal      |
| Time                   | O(n log n)          | O(n log n)            |
| Space                  | O(n)                | O(n)                  |

---

# Which should you use?

For interviews:

* ✅ Learn **DFS first** because it is shorter and demonstrates recursion with coordinate tracking.
* ✅ Learn **BFS** because many tree-view problems (Top View, Bottom View, Level-based views) naturally use queues.

Both are accepted for LeetCode 987. The key idea in both approaches is the same: store nodes grouped by **column**, then **row**, and finally sort values that share the same position.


The `log n` factor comes from ordered `map` and `multiset` insertions.
