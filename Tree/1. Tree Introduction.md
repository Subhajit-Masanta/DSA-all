# Tree Introduction

## What is a Tree?

A **Tree** is a **non-linear hierarchical data structure** made up of **nodes** connected by **edges**.

Unlike arrays and linked lists, where elements are arranged sequentially, trees organize data in **parent-child relationships**, making them ideal for representing hierarchical information.

A tree starts with a single node called the **Root**, from which all other nodes originate.

Example:

```text
        A
      /   \
     B     C
    / \   / \
   D   E F   G
```

---

# Why Do We Need Trees?

Arrays and Linked Lists are excellent for storing sequential data, but many real-world problems involve hierarchical relationships.

Examples include:

* File System
* Organization Chart
* Family Tree
* HTML DOM
* Decision Trees
* Game Trees
* Database Indexes

Representing these structures using arrays or linked lists becomes difficult and inefficient. Trees naturally model such relationships.

---

# Arrays vs Linked Lists vs Trees

## Array

```text
10 20 30 40 50
```

**Advantages**

* Fast random access (O(1))
* Simple implementation

**Limitations**

* Fixed-size (in many implementations)
* Poor at representing hierarchical relationships

---

## Linked List

```text
10 → 20 → 30 → 40
```

**Advantages**

* Dynamic size
* Easy insertion and deletion

**Limitations**

* Each node points to only one next node
* Cannot naturally represent branching

---

## Tree

```text
        CEO
       /   \
 ManagerA  ManagerB
   /  \       |
Emp1 Emp2   Emp3
```

**Advantages**

* Naturally represents hierarchical relationships
* Efficient searching and traversal for many applications
* Forms the basis of several advanced data structures

# Basic Components of a Tree

Consider the following tree:

```text
        A
      /   \
     B     C
    / \
   D   E
```

The tree consists of:

* **Nodes** – Individual elements (A, B, C, D, E)
* **Edges** – Connections between nodes

Each node stores:

* Data (value)
* References (pointers) to its child nodes

---

# Characteristics of Trees

* Hierarchical data structure
* Non-linear structure
* Starts from one Root node
* Contains parent-child relationships
* Connected structure
* Contains no cycles
* Exactly one unique path exists between any two nodes
* Every subtree is itself a tree

---

# General Tree vs Binary Tree

## General Tree

A node may have any number of children.

```text
        A
      / | | \
     B  C D  E
```

---

## Binary Tree

A node can have **at most two children**.

```text
      A
     / \
    B   C
```

Almost all coding interview questions initially focus on **Binary Trees**.

---

# Why Trees are Important in DSA

Trees appear in numerous placement questions because they combine:

* Recursion
* Divide and Conquer
* Depth-First Search (DFS)
* Breadth-First Search (BFS)
* Dynamic Programming on Trees
* Binary Search Tree concepts

Mastering trees builds the foundation for Graphs, Tries, Heaps, Segment Trees, Fenwick Trees, and many advanced algorithms.

---

# The Most Important Mindset Shift

While solving tree problems, **do not think of the entire tree at once**.

Instead, think recursively:

> **"If I can solve the left subtree and the right subtree, can I solve the current node?"**

This recursive thinking is the key to almost every tree algorithm.
