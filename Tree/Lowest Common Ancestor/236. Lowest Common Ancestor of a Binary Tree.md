# 236. Lowest Common Ancestor of a Binary Tree

| Topic | Difficulty | Pattern                     |
| ----- | ---------- | --------------------------- |
| Tree  | Medium     | Bottom-Up DFS / Return Node |

---

# 📌 Problem Description

Given two nodes **p** and **q** in a binary tree, find their **Lowest Common Ancestor (LCA)**.

The LCA is the **deepest node** that has both **p** and **q** as descendants.

> **Important:** A node is considered a **descendant of itself**.

---

# 🧠 Understanding the Question

Example

```text
              3
           /     \
          5       1
        /   \    / \
       6     2  0   8
            / \
           7   4
```

### Example 1

```text
p = 5
q = 1
```

Common ancestors

```text
3
```

Answer

```text
3
```

---

### Example 2

```text
p = 5
q = 4
```

Many people think answer is

```text
3
```

Wrong.

Why?

Because the problem says

> A node is a descendant of itself.

Descendants of **5**

```text
5

6

2

7

4
```

Therefore

```text
5

contains

5

and

4
```

So

```text
LCA = 5
```

# 🧠 New Pattern

This is the first tree problem where recursion returns

```cpp
TreeNode*
```

instead of

```cpp
int
```

or

```cpp
bool
```

Each recursive call returns one of only four things

```text
nullptr

or

p

or

q

or

LCA
```

The answer is built while returning from recursion (Bottom-Up).

---

# 🎯 Intuition

Every node asks its children

```text
Did you find

p

or

```

Left child replies

```text
or

```

Right child replies

```text
nullptr
```

Current node combines those two answers.

# Base Cases

```cpp
if(root == nullptr)
    return nullptr;

if(root == p || root == q)
    return root;
```

Why?

If we find one of the target nodes,

we return it upward.

The parent will decide whether it is the LCA.

---

# Four Cases

After recursion

```cpp
TreeNode* left = solve(root->left,p,q);

TreeNode* right = solve(root->right,p,q);
```

---

## Case 1

```text
left = nullptr

right = nullptr
```

Neither subtree contains p or q.

Return

```text
nullptr
```

---

## Case 2

```text
left = p

right = nullptr
```

One target found in left subtree.

Pass it upward.

```cpp
return left;
```

---

## Case 3

```text
left = nullptr

right = q
```

One target found in right subtree.

Pass it upward.

```cpp
return right;
```

---

## ⭐ Case 4

```text
left = p

right = q
```

One target found in each subtree.

Current node is where both paths meet.

Return

```cpp
return root;
```

This is the Lowest Common Ancestor.

---

# Algorithm

```text
Current Node

↓

Base Cases

↓

Search Left

↓

Search Right

↓

Both Found?

↓

Yes

↓

Return Root

↓

Else

↓

Return Non-null Child
```

---

# Code

```cpp
class Solution {
public:

    TreeNode* lowestCommonAncestor(TreeNode* root,
                                   TreeNode* p,
                                   TreeNode* q) {

        if(root == nullptr)
            return nullptr;

        if(root == p || root == q)
            return root;

        TreeNode* left = lowestCommonAncestor(root->left,p,q);

        TreeNode* right = lowestCommonAncestor(root->right,p,q);

        if(left && right)
            return root;

        if(left)
            return left;

        return right;
    }
};
```

# Why does `p = 5, q = 4` return 5?

Tree

```text
        5
       / \
      6   2
         / \
        7   4
```

Recursion reaches

```text
5
```

Immediately

```cpp
if(root == p)
    return root;
```

returns

```text
5
```

The algorithm does **not** explicitly check whether 5 is an ancestor of 4.

It relies on the problem's definition:

```text
A node is a descendant of itself.
```

Since 5 is itself one target and 4 lies in its subtree, **5 already satisfies the LCA definition**. The recursive returns naturally propagate this result upward.

---

# Common Mistakes

## ❌ Returning root when only one side is non-null

Wrong

```cpp
return root;
```

Correct

```cpp
return left;
```

or

```cpp
return right;
```

Otherwise you overwrite the correct answer.

---

## ❌ Forgetting the base case

```cpp
if(root == p || root == q)
```

Without it,

the recursion never reports that it found one of the targets.

---

## ❌ Thinking recursion knows ancestor relationships

It doesn't.

The recursion simply returns nodes upward.

The parent combines the answers.

# Key Takeaways

* First tree problem that returns a **TreeNode*** from recursion.
* This is a **Bottom-Up DFS** pattern.
* Each recursive call returns either `nullptr`, `p`, `q`, or an LCA.
* If both left and right return non-null, the current node is the LCA.
* If only one side returns non-null, propagate that node upward.
* A node is considered a descendant of itself, which is why an ancestor can be the LCA when one target lies in its subtree.
