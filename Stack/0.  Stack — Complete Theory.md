# Stack — Complete Theory for EY

## 1. What Is a Stack?

A **Stack** is a linear data structure that follows:

> **LIFO — Last In, First Out**

Insertion and deletion happen only at one end called the **TOP**.

```text
        TOP
         ↓
       | 40 |
       | 30 |
       | 20 |
       | 10 |
       ------
```

The last inserted element (`40`) is removed first.

---

# 2. Why Do We Need a Stack?

We use a stack when the problem naturally requires:

> **The most recently added/active item to be processed first.**

Examples:

* Function calls
* Recursion
* Undo operations
* Browser back
* Parentheses matching
* Expression evaluation
* DFS
* Backtracking

### Core idea

```text
Normal unrestricted access
        ↓
      Array

Need LIFO behavior
        ↓
      Stack
```

A stack intentionally restricts access to the **top** to enforce LIFO behavior.

---

# 3. Basic Operations

| Operation      | Meaning                   | Time |
| -------------- | ------------------------- | ---: |
| `push(x)`      | Add `x` to top            | O(1) |
| `pop()`        | Remove top                | O(1) |
| `top()/peek()` | View top without removing | O(1) |
| `empty()`      | Check whether empty       | O(1) |
| `size()`       | Number of elements        | O(1) |

### Example

```text
push(10)
push(20)
push(30)

      TOP
       ↓
      30
      20
      10

pop()  → removes 30
top()  → returns 20
```

---

# 4. Stack Overflow vs Underflow

## Overflow

Trying to insert into a **full fixed-capacity stack**.

```text
Capacity = 3

[30]
[20]
[10]

push(40) → OVERFLOW
```

## Underflow

Trying to remove from an **empty stack**.

```text
Stack = empty

pop() → UNDERFLOW
```

### Remember

```text
Push on full  → Overflow
Pop on empty  → Underflow
```

---

# 5. Stack Implementations

A stack can be implemented using:

1. Array
2. Linked List
3. Dynamic array (`vector`) in practical C++

The behavior remains the same:

```text
LIFO
```

---

# 6. Array vs Linked List Stack

| Feature              | Array              | Linked List             |
| -------------------- | ------------------ | ----------------------- |
| Memory               | Contiguous         | Non-contiguous          |
| Size                 | Fixed normally     | Dynamic                 |
| Push                 | O(1)               | O(1)                    |
| Pop                  | O(1)               | O(1)                    |
| Peek                 | O(1)               | O(1)                    |
| Extra pointer memory | No                 | Yes                     |
| Cache locality       | Better             | Worse                   |
| Overflow             | When capacity full | When memory unavailable |
| Implementation       | Simpler            | More complex            |

### When to choose Array?

Choose array when:

* Maximum size is known
* Memory should be contiguous
* Simplicity and cache performance matter
* Fixed capacity is acceptable

### When to choose Linked List?

Choose linked list when:

* Size is unpredictable
* Dynamic growth is important
* You don't want a fixed capacity

### Important

Both provide:

```text
push → O(1)
pop  → O(1)
```

The main difference is **memory management**, not stack behavior.

---

# 7. Stack vs Array

These are not exactly competing data structures.

### Array

Provides:

```cpp
arr[0]
arr[1]
arr[2]
```

Allows arbitrary indexed access.

### Stack

Provides restricted access:

```text
TOP only
```

### Key distinction

> **Array = storage structure**
> **Stack = LIFO ADT**

A stack can be implemented using an array.

---

# 8. Stack vs Queue

| Feature   | Stack                | Queue           |
| --------- | -------------------- | --------------- |
| Principle | LIFO                 | FIFO            |
| Insert    | Top                  | Rear            |
| Remove    | Top                  | Front           |
| Example   | Stack of plates      | Line of people  |
| Main use  | Undo, recursion, DFS | Scheduling, BFS |

```text
STACK

10
20
30 ← remove first
```

```text
QUEUE

10 → 20 → 30
↑
remove first
```

### When to choose?

Use **Stack** when:

> Most recent item should be processed first.

Use **Queue** when:

> Oldest item should be processed first.

---

# 9. Stack vs Deque

A **Deque (Double-Ended Queue)** allows insertion and deletion at **both ends**.

```text
FRONT ← [10][20][30] → REAR
```

Stack:

```text
Only one end
        ↓
      TOP
```

Deque:

```text
Both ends
↓       ↓
FRONT  REAR
```

### When to choose?

```text
Need LIFO only
    → Stack

Need FIFO only
    → Queue

Need operations at both ends
    → Deque
```

A deque can also be used to implement a stack or queue.

---

# 10. Stack vs Priority Queue

These are fundamentally different.

### Stack

Removal depends on:

```text
Insertion order
→ newest first
```

### Priority Queue

Removal depends on:

```text
Priority
→ highest/lowest priority first
```

### Example

```text
Stack:
A → B → C
remove → C

Priority Queue:
A(priority 2)
B(priority 10)
C(priority 5)

remove → B
```

### When to choose?

```text
Newest first       → Stack
Highest priority   → Priority Queue
```

---

# 11. Stack vs Linked List

A linked list allows access/manipulation of nodes from different positions.

A stack restricts operations to the top.

```text
Linked List:
10 → 20 → 30 → 40
      ↑
Can traverse

Stack:
10 → 20 → 30 → 40
                 ↑
               TOP
```

A linked list can be used **to implement** a stack.

---

# 12. Stack as an ADT

Stack is an **Abstract Data Type (ADT)**.

ADT describes:

> **What operations and behavior are provided, not how they are implemented.**

```text
Stack ADT
│
├── push()
├── pop()
├── top()
├── empty()
└── size()
```

It can internally use:

```text
Array
Linked List
Dynamic Array
```

---

# 13. Why Not Just Use an Array?

Because sometimes unrestricted access is undesirable.

Suppose:

```text
A
B
C
D
```

If the requirement is:

> Always process the most recently added item first.

A normal array doesn't enforce this.

A stack guarantees:

```text
D → C → B → A
```

This makes the intended behavior explicit and prevents invalid access patterns.

# 14. Major Applications

## 1. Function Calls

```text
main()
 ↓
foo()
 ↓
bar()
```

Return order:

```text
bar()
 ↓
foo()
 ↓
main()
```

LIFO behavior.

---

## 2. Recursion

```text
factorial(3)
    ↓
factorial(2)
    ↓
factorial(1)
```

Function calls are maintained on the runtime **call stack**.

Deep recursion can cause:

> Stack Overflow

---

## 3. Parentheses Matching

```text
({[]})
```

Opening brackets are pushed.

For a closing bracket:

```text
check top
↓
match?
↓
pop
```

Why stack?

Because the **most recently opened bracket must be closed first**.

---

## 4. Undo

```text
Action A
Action B
Action C
```

Undo:

```text
C
B
A
```

LIFO.

---

## 5. Browser Back

```text
Google
 ↓
YouTube
 ↓
GitHub
```

Back:

```text
GitHub → YouTube → Google
```

---

## 6. DFS

DFS can use:

```text
Recursion
```

or an explicit:

```text
Stack
```

---

## 7. Backtracking

Examples:

* Maze solving
* Permutations
* Subsets
* N-Queens

Previous states can be stored and restored using stack-like behavior.

---

## 8. Expression Processing

Stacks are used in:

* Infix → Postfix
* Infix → Prefix
* Postfix evaluation
* Operator precedence handling

For EY, know the concept and basic problems; don't over-invest in obscure expression tricks unless specifically required.

# 16. C++ STL Stack

```cpp
#include <stack>

using namespace std;

stack<int> st;
```

### Push

```cpp
st.push(10);
st.push(20);
```

### Top

```cpp
cout << st.top();
```

### Pop

```cpp
st.pop();
```

### Empty

```cpp
st.empty();
```

### Size

```cpp
st.size();
```

---

# 17. Important C++ Trap

`pop()` **does not return the removed element**.

Wrong:

```cpp
int x = st.pop();   // ❌
```

Correct:

```cpp
int x = st.top();
st.pop();
```

# 21. Decision Rule — When Should I Think "Stack"?

When you see:

```text
"Last added"
"Most recent"
"Reverse order"
"Undo"
"Back"
"Nested"
"Matching brackets"
"Function calls"
"Recursion"
"Backtracking"
"DFS"
```

Think:

> **STACK**

But don't blindly use a stack just because the problem says "reverse." Check whether the required behavior is actually LIFO.
