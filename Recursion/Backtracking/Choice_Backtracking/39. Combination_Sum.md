# 📌 Problem Description

Given an array of **distinct integers** and a target,

find all unique combinations whose sum equals the target.

Each number can be used **unlimited times**.

Example

```text
Input

candidates = [2,3,6,7]

target = 7

Output

[2,2,3]

[7]
```

---

# 🧠 Core Insight

This is almost identical to **Subsets II**.

Only one rule changes.

## Subsets II

```text
Choose 2

↓

Can't choose 2 again

↓

solve(i+1)
```

---

## Combination Sum

```text
Choose 2

↓

Can choose 2 again

↓

solve(i)
```

Only one line changes.

```text
Current Combination

↓

Loop through choices

↓

Choose element

↓

Update sum

↓

Recursive call

↓

Undo choice

↓

Continue loop
```

# 🔄 Why solve(i) ?

Suppose

```text
Current

[2]
```

Can we choose

```text

```

again?

YES.

So recursion should still start from

```text

```

## Correct

```text

↓

solve(i)
```

```text

```

Suppose

```text

[2,3]
```

Calling

```text

```

allows

```text

↓

↓

```

giving

```text

```

which is the same combination as

```text
[2,2,3]
```

Different order, duplicate answer.

# 💻 Code (C++)

```cpp
class Solution {
public:

    void solve(int index,
               vector<int>& candidates,
               int target,
               vector<int>& current,
               int currentSum,
               vector<vector<int>>& ans)
    {
        if(currentSum == target)
        {
            ans.push_back(current);
            return;
        }

        if(currentSum > target)
            return;

        for(int i=index;i<candidates.size();i++)
        {
            current.push_back(candidates[i]);

            solve(i,
                  candidates,
                  target,
                  current,
                  currentSum + candidates[i],
                  ans);

            current.pop_back();
        }
    }

    vector<vector<int>> combinationSum(vector<int>& candidates,
                                       int target)
    {
        vector<vector<int>> ans;
        vector<int> current;

        solve(0,candidates,target,current,0,ans);

        return ans;
    }
};
```

# ⏱ Time Complexity

Worst case

```text
Each level

↓

Multiple choices

↓

Exponential recursion
```

Approximately

```text
O(2^target)
```

(Depends on target and candidate values.)

Copying every valid combination costs extra

```text
O(k)
```

where

```text
k = size of current combination
```

---

# 📦 Space Complexity

Recursion depth

```text
Maximum

target / smallest candidate

↓

O(target)
```

Current vector

```text
O(target)
```

Auxiliary Space

```text
O(target)
```

(Result storage excluded.)

# ⚠️ Common Mistakes

❌ Using

```cpp
solve(0,...)
```

Produces

```text
[2,3,2]

[3,2,2]
```

Duplicate combinations.

---

❌ Using

```cpp
solve(i+1,...)
```

Misses

```text
[2,2,3]
```

because 2 cannot be reused.

---

❌ Comparing

```cpp
current == target
```

Vector cannot be compared with integer.

Maintain

```text
current vector

+

currentSum
```

or

```text
remainingTarget
```

# 🎯 Interview One-Liner

> **Combination Sum is identical to for-loop backtracking, except after choosing an element we recurse with the same index because every candidate can be used unlimited times.**
