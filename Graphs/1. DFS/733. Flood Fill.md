# 733. Flood Fill

| Topic | Difficulty | Pattern |
|--------|------------|---------|
| Graph | Easy | DFS on Grid |

---

# 📌 Problem Description

You are given an **m × n** image where each cell contains a **color** (integer).

You are also given:

- Starting cell `(sr, sc)`
- New color `color`

Starting from `(sr, sc)`, change its color to the new color.

Then continue changing every **connected cell** that has the **same original color**.

Two cells are connected only if they share a side:

- Up
- Down
- Left
- Right

Return the modified image.

---

## Example 1

Input

```text
image =
[
 [1,1,1],
 [1,1,0],
 [1,0,1]
]

sr = 1
sc = 1
color = 2
```

Output

```text
[
 [2,2,2],
 [2,2,0],
 [2,0,1]
]
```

Explanation

Starting cell

```text
(1,1)
```

Original color

```text
1
```

Every connected **1** becomes **2**.

Bottom-right **1** does **not** change because it is separated by **0**.

---

## Example 2

Input

```text
image =
[
 [0,0,0],
 [0,0,0]
]

sr = 0
sc = 0
color = 0
```

Output

```text
[
 [0,0,0],
 [0,0,0]
]
```

Nothing changes because the starting pixel already has the target color.


# Why Store Old Color?

Suppose

```text
1 1

1 1
```

Start at

```text
(0,0)
```

New Color

```text
2
```

After changing

```text
2 1

1 1
```

The next DFS call must still look for

```text
1
```

NOT

```text
2
```

Therefore,

```cpp
oldColor = image[sr][sc];
```

is stored **before DFS starts**.

---

# Why No Visited Array?

Changing

```text
Old Color

↓

New Color
```

automatically marks the cell as visited.

Example

```text
1

↓

2
```

Later,

```cpp
image[row][col] != oldColor
```

stops DFS from revisiting it.

---

# Algorithm

```text
Store Old Color

↓

Old Color == New Color ?

↓

Return Image

↓

DFS

↓

Outside Grid ?

↓

Return

↓

Current Color != Old Color ?

↓

Return

↓

Paint Current Cell

↓

Visit

Up

Down

Left

Right
```

---

# Code

```cpp
class Solution {
public:

    void dfs(vector<vector<int>>& image,
             int row,
             int col,
             int oldColor,
             int newColor)
    {
        int rows = image.size();
        int cols = image[0].size();

        if(row < 0 || row >= rows ||
           col < 0 || col >= cols ||
           image[row][col] != oldColor)
        {
            return;
        }

        image[row][col] = newColor;

        dfs(image, row - 1, col, oldColor, newColor);
        dfs(image, row + 1, col, oldColor, newColor);
        dfs(image, row, col - 1, oldColor, newColor);
        dfs(image, row, col + 1, oldColor, newColor);
    }

    vector<vector<int>> floodFill(vector<vector<int>>& image,
                                  int sr,
                                  int sc,
                                  int color)
    {
        int oldColor = image[sr][sc];

        if(oldColor == color)
            return image;

        dfs(image, sr, sc, oldColor, color);

        return image;
    }
};
```

# Common Mistakes

## ❌ Forgetting Old Color

Wrong

```cpp
image[row][col] == color
```

Correct

```cpp
image[row][col] == oldColor
```

---

## ❌ Not Handling

```cpp
oldColor == newColor
```

Without this,

DFS keeps revisiting cells because their value never changes.

---

## ❌ Creating a Visited Array

Not required.

Changing the color already marks the cell as visited.

---

## ❌ Visiting Diagonals

Only

```text
Up

Down

Left

Right
```

are valid neighbours.

---

# Complexity

| Complexity | Value |
|------------|-------|
| Time | **O(m × n)** |
| Auxiliary Space | **O(m × n)** |

### Time

Each cell is visited at most once.

```text
Rows × Columns

↓

O(m × n)
```

### Auxiliary Space

Worst case recursion stack contains every cell.

```text
O(m × n)
```

---

# Key Takeaways

- Store the **old color** before starting DFS.
- If `oldColor == newColor`, return immediately.
- No visited array is required.
- Changing the color automatically marks the cell as visited.
- DFS spreads only through cells having the **same original color**.
