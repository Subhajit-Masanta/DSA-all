# Number of Ways to Arrive at Destination (LeetCode 1976)

| Topic | Difficulty | Pattern |
|--------|------------|---------|
| Graph | Medium | Dijkstra + Counting Shortest Paths |

---

# 📌 Problem Description

You are given

```cpp
n
```

intersections connected by bidirectional weighted roads.

Each road is represented as

```cpp
u ↔ v (time)
```

You start from

```text
0
```

and want to reach

```text
n-1
```

Find

- The **shortest travel time**
- The **number of different shortest paths**

Return the number of shortest paths modulo

```text
10^9 + 7
```

# 🧠 Intuition

Normal Dijkstra only asks

```text
What is the shortest distance?
```

This problem asks

```text
What is the shortest distance?

AND

How many shortest paths exist?
```

So,

besides storing

```cpp
dist[node]
```

we also store

```cpp
ways[node]
```

---

# Key Observation

For every node,

store

```cpp
dist[node]
```

meaning

```text
Shortest distance
```

and

```cpp
ways[node]
```

meaning

```text
Number of shortest paths
```

Initially

```cpp
dist[0]=0;

ways[0]=1;
```

because

```text
There is exactly one way
to reach the source.

(Start there.)
```

---

During relaxation,

there are only **two possibilities**.

---

## Case 1

Found a **smaller distance**

```cpp
newDist < dist[neighbour]
```

Old shortest path is no longer useful.

Update

```cpp
dist[neighbour]=newDist;

ways[neighbour]=ways[node];
```

Notice

we **copy**

the number of ways.

---

## Case 2

Found another path with the **same shortest distance**

```cpp
newDist == dist[neighbour]
```

We found one more shortest path.

Update

```cpp
ways[neighbour]

+=

ways[node]
```

Take modulo

```cpp
ways[neighbour]

=

(ways[neighbour]+ways[node])

% MOD;
```

---

# Algorithm

```text
Build Adjacency List

↓

Distance Array = INF

↓

Ways Array = 0

↓

dist[0]=0

ways[0]=1

↓

Push (0,0)

↓

While Priority Queue Not Empty

↓

Pop Minimum Distance Node

↓

Ignore Stale Entry

↓

Traverse Neighbours

↓

newDist=currentDist+weight

↓

Smaller Distance?

↓

Update Distance

↓

Copy Ways

↓

Push into Priority Queue

↓

Equal Distance?

↓

Add Ways

↓

Priority Queue Empty

↓

Return ways[n-1]
```

# Code

```cpp
class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {

        vector<vector<pair<int,int>>> adj(n);

        for(auto road : roads)
        {
            int u = road[0];
            int v = road[1];
            int wt = road[2];

            adj[u].push_back({v,wt});
            adj[v].push_back({u,wt});
        }

        const int MOD = 1e9 + 7;

        vector<long long> dist(n, LLONG_MAX);
        vector<int> ways(n,0);

        priority_queue<
        pair<long long,int>,
        vector<pair<long long,int>>,
        greater<pair<long long,int>>
        > pq;

        dist[0]=0;
        ways[0]=1;

        pq.push({0,0});

        while(!pq.empty())
        {
            auto [currentDist,node]=pq.top();
            pq.pop();

            if(currentDist>dist[node])
                continue;

            for(auto [neigh,wt]:adj[node])
            {
                long long newDist=currentDist+wt;

                if(newDist<dist[neigh])
                {
                    dist[neigh]=newDist;

                    ways[neigh]=ways[node];

                    pq.push({newDist,neigh});
                }

                else if(newDist==dist[neigh])
                {
                    ways[neigh]=
                    (ways[neigh]+ways[node])%MOD;
                }
            }
        }

        return ways[n-1];
    }
};
```

# Why Dijkstra Works?

The priority queue always pops the node with the

```text
Smallest Distance So Far
```

When a shorter path is found,

we replace both

```text
Distance

and

Ways
```

When another shortest path is found,

we simply add its number of ways.

Thus,

every node always stores

```text
Shortest Distance

+

Number of Shortest Paths
```

# Common Mistakes

## ❌ Using int for Distance

Wrong

```cpp
vector<int> dist;
```

Road weights can exceed

```text
2 × 10^9
```

Correct

```cpp
vector<long long> dist;
```

---

## ❌ Forgetting to Push into Priority Queue

After updating distance

Always

```cpp
pq.push({newDist,neighbour});
```

---

## ❌ Incrementing Ways on Better Distance

Wrong

```cpp
ways[neighbour]+=ways[node];
```

Correct

```cpp
ways[neighbour]=ways[node];
```

because the old shortest path is no longer valid.

---

## ❌ Forgetting Modulo

Wrong

```cpp
ways[neighbour]+=ways[node];
```

Correct

```cpp
ways[neighbour]=
(ways[neighbour]+ways[node])%MOD;
```

---

## ❌ Forgetting Stale Entry Check

Always

```cpp
if(currentDist>dist[node])
    continue;
```

---

## ❌ Using Assignment Instead of Comparison

Wrong

```cpp
if(dist[v]=newDist)
```

Correct

```cpp
if(dist[v]==newDist)
```

# Complexity

| Complexity | Value |
|------------|-------|
| Time | **O((V + E) log V)** |
| Auxiliary Space | **O(V + E)** |

### Why?

- Every edge is relaxed during Dijkstra.
- Each push/pop from the priority queue takes

```text
log V
```

- Distance array, ways array, and adjacency list store graph information.

---

# Key Takeaways

- This is **Dijkstra with path counting**.
- `dist[node]` stores the **shortest distance**.
- `ways[node]` stores the **number of shortest paths**.
- On a **smaller distance**, copy the number of ways.

```cpp
ways[v]=ways[u];
```

- On an **equal distance**, add the number of ways.

```cpp
ways[v]=(ways[v]+ways[u])%MOD;
```

- Use **long long** for distances.
- Always ignore stale priority queue entries.
- Return

```cpp
ways[n-1];
```
