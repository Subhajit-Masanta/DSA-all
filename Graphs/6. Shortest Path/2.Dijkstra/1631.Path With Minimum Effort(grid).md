# 1631 Path With Minimum Effort (LeetCode 1631)

| Topic | Difficulty | Pattern |
|--------|------------|---------|
| Graph | Medium | Grid + Dijkstra |

# 📌 Problem Description

You are given a grid

```cpp
heights[row][col]
```

where each cell represents the height of that position.

You start from

```text
(0,0)
```

and want to reach

```text
(rows-1,cols-1)
```

You can move

- Up
- Down
- Left
- Right

The cost of moving between two adjacent cells is

```cpp
abs(height1-height2)
```

The **effort of a path** is

```text
Maximum absolute difference
between any two consecutive cells
```

Return the **minimum effort** required to reach the destination.

# 🧠 Intuition

Normal Dijkstra minimizes

```text
Sum of edge weights
```

This problem asks us to minimize

```text
Maximum edge weight
```

So,

instead of storing

```text
Shortest Distance
```

we store

```text
Minimum Effort
```

required to reach every cell.

---

# Key Observation

Suppose

Current Effort

```text
2
```

Current Edge Cost

```text
5
```

The new path effort becomes

```cpp
max(2,5)
```

NOT

```cpp
2+5
```

---

Therefore,

Relaxation changes from

```cpp
dist[node] + weight
```

to

```cpp
max(currEffort, edgeCost)
```

# Grid Neighbours

Unlike graphs,

there is no adjacency list.

Generate neighbours using

```cpp
int dr[]={-1,1,0,0};
int dc[]={0,0,-1,1};
```

| i | Move |
|---|------|
|0|Up|
|1|Down|
|2|Left|
|3|Right|

Generate neighbour

```cpp
int newRow=currRow+dr[i];
int newCol=currCol+dc[i];
```

Boundary Check

```cpp
if(newRow>=0 && newRow<rows &&
   newCol>=0 && newCol<cols)
```

# Algorithm

```text
Distance Matrix = INF

↓

dist[0][0]=0

↓

Push (0,0,0)

↓

While Priority Queue Not Empty

↓

Pop Minimum Effort Cell

↓

Ignore Stale Entry

↓

If Destination

↓

Return Current Effort

↓

Generate 4 Neighbours

↓

Find Edge Cost

↓

edgeCost = abs(height difference)

↓

newEffort = max(currEffort,edgeCost)

↓

Better than dist?

↓

Update

↓

Push into Priority Queue

↓

Destination Reached

↓

Return Minimum Effort
```

---

# Code

```cpp
class Solution {
public:

    int minimumEffortPath(vector<vector<int>>& heights)
    {
        int rows = heights.size();
        int cols = heights[0].size();

        vector<vector<int>> dist(rows, vector<int>(cols, INT_MAX));

        dist[0][0] = 0;

        priority_queue<
        tuple<int,int,int>,
        vector<tuple<int,int,int>>,
        greater<tuple<int,int,int>>
        > pq;

        pq.push({0,0,0});

        int dr[] = {-1,1,0,0};
        int dc[] = {0,0,-1,1};

        while(!pq.empty())
        {
            auto [currEffort,row,col] = pq.top();
            pq.pop();

            if(currEffort > dist[row][col])
                continue;

            if(row==rows-1 && col==cols-1)
                return currEffort;

            for(int i=0;i<4;i++)
            {
                int newRow = row + dr[i];
                int newCol = col + dc[i];

                if(newRow>=0 && newRow<rows &&
                   newCol>=0 && newCol<cols)
                {
                    int edgeCost = abs(
                        heights[row][col] -
                        heights[newRow][newCol]
                    );

                    int newEffort = max(currEffort, edgeCost);

                    if(newEffort < dist[newRow][newCol])
                    {
                        dist[newRow][newCol] = newEffort;

                        pq.push({newEffort,newRow,newCol});
                    }
                }
            }
        }

        return 0;
    }
};
```

# Why Dijkstra Works?

The priority queue always pops the cell with the

```text
Smallest Effort So Far
```

The first time the destination is popped,

its effort is already minimum.

So we can immediately

```cpp
return currEffort;
```

# Common Mistakes

## ❌ Using Addition

Wrong

```cpp
currEffort + edgeCost
```

Correct

```cpp
max(currEffort, edgeCost)
```

---

## ❌ Checking Destination by Height

Wrong

```cpp
heights[row][col]
==
heights[lastRow][lastCol]
```

Different cells may have the same height.

Correct

```cpp
row==rows-1 && col==cols-1
```

---

## ❌ Mixing Grid Size with Coordinates

Wrong

```cpp
newRow = rows + dr[i]
```

Correct

```cpp
newRow = row + dr[i]
```

---

## ❌ Wrong Boundary Check

Wrong

```cpp
newRow < row
```

Correct

```cpp
newRow < rows
```

---

## ❌ Forgetting Stale Entry Check

Always

```cpp
if(currEffort > dist[row][col])
    continue;
```

# Complexity

| Complexity | Value |
|------------|-------|
| Time | **O((R × C) log(R × C))** |
| Auxiliary Space | **O(R × C)** |

### Why?

- Every cell may enter the priority queue.
- Every push/pop takes

```text
log(R×C)
```

- Distance matrix stores one value per cell.

---

# Key Takeaways

- This is a **modified Dijkstra**.
- `dist[r][c]` stores the **minimum effort** to reach a cell.
- Priority Queue stores **(Effort, Row, Column)**.
- Relaxation becomes

```cpp
newEffort = max(currEffort, edgeCost);
```

instead of addition.
- Generate neighbours using **direction arrays**.
- No `visited[]` is needed.
- Ignore stale entries using

```cpp
if(currEffort > dist[row][col])
    continue;
```
- Return immediately when the destination is popped from the priority queue.
