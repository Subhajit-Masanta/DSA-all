# 1. Binary Tree

A **Binary Tree** is a tree in which every node has **at most two children**.

The two children are called:

* Left child
* Right child

```text
        10
       /  \
      5    15
     / \
    2   7
```

A node can have:

```text
0 children
1 child
2 children
```

It cannot have 3 children.

### Important

A binary tree does **NOT** have to follow any ordering rule.

Therefore:

```text
        10
       /  \
      20   5
```

is a valid binary tree.

But it is **not a BST**.

---

# 2. Types of Binary Trees

## 2.1 Full Binary Tree

Every node has either:

* 0 children
* 2 children

No node has exactly one child.

```text
        1
       / \
      2   3
         / \
        4   5
```

Valid Full Binary Tree.

```text
        1
       /
      2
```

Not Full.

### Important property

If:

* `I` = number of internal nodes
* `L` = number of leaf nodes

Then:

```text
L = I + 1
```

for a non-empty full binary tree.

---

# 3. Complete Binary Tree

A binary tree is **complete** when:

1. Every level except possibly the last is completely filled.
2. The last level is filled from **left to right**.

Example:

```text
        1
       / \
      2   3
     / \  /
    4   5 6
```

Complete.

But:

```text
        1
       / \
      2   3
       \
        5
```

Not complete because the last level has a gap on the left.

### Key idea

```text
Complete = fill left → right
```

This property is why **binary heaps** use complete binary trees.

---

# 4. Perfect Binary Tree

A binary tree is **perfect** when:

1. Every internal node has exactly 2 children.
2. All leaf nodes are at the same level.

```text
          1
        /   \
       2     3
      / \   / \
     4   5 6   7
```

Everything is completely filled.

### Formula

For height `h`:

```text
Maximum nodes = 2^(h+1) - 1
```

assuming height is measured in edges and root has height 0.

Example:

```text
h = 2

nodes = 2^3 - 1
      = 7
```

---

# 5. Full vs Complete vs Perfect

This is a common confusion.

| Type     | Main Rule                      |
| -------- | ------------------------------ |
| Full     | Every node has 0 or 2 children |
| Complete | Last level filled left → right |
| Perfect  | All levels completely filled   |

### Memory trick

```text
FULL     → 0 or 2 children

COMPLETE → left-to-right filling

PERFECT  → completely filled
```

A perfect binary tree is both:

```text
Full
+
Complete
```

But a full tree doesn't necessarily have to be complete.

---

# 6. Height of a Binary Tree

Height = number of edges on the longest path from the node to a leaf.

For a tree:

```text
        1
       /
      2
     /
    3
```

Height:

```text
2
```

because:

```text
1 → 2 → 3
```

contains 2 edges.

### Important

Some problems define height as number of nodes instead of edges.

So always follow the convention used by the problem.

---

# 7. Maximum Nodes at a Given Level

For a binary tree:

```text
Maximum nodes at level L = 2^L
```

if root is level `0`.

Example:

```text
Level 0 → 1 node
Level 1 → 2 nodes
Level 2 → 4 nodes
Level 3 → 8 nodes
```

Therefore:

```text
Maximum nodes at level L = 2^L
```

---

# 8. Maximum Nodes for Height h

For a binary tree of height `h`:

```text
Maximum nodes = 2^(h+1) - 1
```

Example:

```text
h = 3

maximum nodes
= 2^4 - 1
= 15
```

This occurs in a perfect binary tree.

---

# 9. Minimum Nodes for Height h

For a binary tree with height `h`:

```text
Minimum nodes = h + 1
```

because the minimum-height-efficiency tree can simply be a chain:

```text
1
 \
  2
   \
    3
     \
      4
```

For `h = 3`:

```text
nodes = 4
```

---

# 10. Why Balanced Trees Matter

Consider:

```text
Balanced:

        8
       / \
      4   12
     / \  / \
    2  6 10 14
```

Height is small.

Now consider:

```text
Skewed:

1
 \
  2
   \
    3
     \
      4
       \
        5
```

This behaves almost like a linked list.

### Consequence

For operations based on height:

```text
Balanced tree → approximately O(log N)

Skewed tree → O(N)
```

This becomes extremely important for BSTs.

---

# 11. Skewed Binary Tree

A binary tree where every node has at most one child.

Example:

```text
1
 \
  2
   \
    3
     \
      4
```

or:

```text
      4
     /
    3
   /
  2
 /
1
```

It is effectively behaving like a linked list.

---

# 12. BST — Binary Search Tree

A **Binary Search Tree** is a binary tree with an ordering property.

For every node:

```text
All values in left subtree < node
All values in right subtree > node
```

Example:

```text
          8
        /   \
       4     12
      / \    / \
     2   6  10 14
```

This allows efficient searching.

---

# 13. Why BST is Useful

Suppose we search for `10`.

```text
          8
        /   \
       4     12
            /
           10
```

Start:

```text
10 > 8
```

So ignore the left subtree.

Then:

```text
10 < 12
```

Go left.

Found `10`.

Instead of checking every node, we repeatedly eliminate half of the search space **when the tree is balanced**.

---

# 14. BST Search Complexity

### Balanced BST

```text
O(log N)
```

### Worst-case skewed BST

```text
O(N)
```

Example:

```text
1
 \
  2
   \
    3
     \
      4
```

Searching for `4` requires walking through every node.

---

# 15. BST Operations

The basic operations are:

```text
Search
Insert
Delete
Find Minimum
Find Maximum
```

For a balanced BST:

```text
Search  → O(log N)
Insert  → O(log N)
Delete  → O(log N)
```

Worst case:

```text
Search  → O(N)
Insert  → O(N)
Delete  → O(N)
```

---

# 16. BST Minimum and Maximum

In a BST:

```text
Minimum → keep going LEFT

Maximum → keep going RIGHT
```

Example:

```text
          8
        /   \
       4     12
      / \    / \
     2   6  10 14
```

Minimum:

```text
8 → 4 → 2
```

Therefore:

```text
min = 2
```

Maximum:

```text
8 → 12 → 14
```

Therefore:

```text
max = 14
```

---

# 17. BST Inorder Property

This is one of the most important facts:

> **Inorder traversal of a BST produces elements in sorted order.**

Example:

```text
          8
        /   \
       4     12
      / \    / \
     2   6  10 14
```

Inorder:

```text
2 4 6 8 10 12 14
```

Therefore:

```text
BST
 ↓
Inorder
 ↓
Sorted sequence
```

This is frequently useful in interview problems.

---

# 18. How to Check Whether a Binary Tree Is a BST

A common mistake is checking only:

```text
left child < root < right child
```

That is **not sufficient**.

Example:

```text
        10
       /  \
      5    15
          /
         6
```

At first glance:

```text
6 < 15
```

looks fine.

But `6` is in the **right subtree of 10**.

Therefore:

```text
6 must be > 10
```

It isn't.

So this is NOT a BST.

### Correct idea

Every node must obey the valid range inherited from its ancestors.

For example:

```text
Root = 10

Left subtree:
(-∞, 10)

Right subtree:
(10, +∞)
```

When moving into the left side of 10, the upper bound becomes 10.

When moving into the right side, the lower bound becomes 10.

---

# 19. BST Insertion — Theory

To insert a value:

1. Start at root.
2. Compare value with current node.
3. Smaller → go left.
4. Larger → go right.
5. Continue until an empty position is found.
6. Insert there.

Example: insert `7`

```text
        8
       /
      4
       \
        6
```

Since:

```text
7 < 8 → left
7 > 4 → right
7 > 6 → right
```

Insert:

```text
        8
       /
      4
       \
        6
         \
          7
```

---

# 20. BST Deletion — 3 Cases

This is important theory even if you don't code it immediately.

Suppose we delete a node.

## Case 1 — Leaf

```text
      5
     / \
    3   7
```

Delete `3`.

Simply remove it.

---

## Case 2 — One Child

```text
      5
     /
    3
     \
      4
```

Delete `3`.

Connect its parent directly to its child:

```text
      5
     /
    4
```

---

## Case 3 — Two Children ⭐

```text
        8
       / \
      4   12
     / \
    2   6
```

Delete `4`.

It has two children.

We can replace it with:

* Inorder successor
* OR inorder predecessor

### Inorder successor

The **smallest value in the right subtree**.

For `4`:

```text
right subtree = 6
successor = 6
```

Replace 4 with 6.

---

# 21. Inorder Successor vs Predecessor

For a BST:

### Inorder Successor

The next larger element.

```text
smallest element in right subtree
```

### Inorder Predecessor

The next smaller element.

```text
largest element in left subtree
```

Memory:

```text
Successor → go RIGHT, then LEFT as much as possible

Predecessor → go LEFT, then RIGHT as much as possible
```

---

# 22. Balanced BST

A balanced BST keeps its height relatively small.

Why?

Because BST operation complexity depends heavily on height.

```text
O(height)
```

If:

```text
height ≈ log N
```

then:

```text
operations ≈ O(log N)
```

If:

```text
height ≈ N
```

then:

```text
operations ≈ O(N)
```

---

# 23. Self-Balancing Trees

A self-balancing BST automatically maintains its height.

Examples:

* AVL Tree
* Red-Black Tree

### EY priority

Know:

> Self-balancing trees prevent a BST from becoming excessively skewed, helping maintain approximately logarithmic height.

You do **not** need to deeply study AVL rotations for the basic EY preparation unless the interviewer specifically goes deeper.

# 24. Tree Recursion — The Core Pattern

Many binary-tree problems use recursion.

The general pattern is:

```text
solve(root):

    if root == NULL:
        return base case

    solve(root->left)
    solve(root->right)

    combine results
```

The key idea:

> A tree is naturally recursive because every subtree is itself a tree.

For example:

```text
        1
       / \
      2   3
     / \
    4   5
```

The left subtree:

```text
      2
     / \
    4   5
```

is itself a tree.

The right subtree:

```text
3
```

is also a tree.

This is why recursion fits tree problems so naturally.

---

# 25. Common Tree Recursion Pattern

For height:

```text
height(root)

    if root is NULL:
        return 0

    leftHeight = height(root->left)
    rightHeight = height(root->right)

    return 1 + max(leftHeight, rightHeight)
```

The important conceptual structure is:

```text
Solve left
Solve right
Combine
```

You will see this pattern repeatedly.

# 26. Binary Tree vs BST vs Heap

These are often confused.

| Property           | Binary Tree            | BST                 | Binary Heap                  |
| ------------------ | ---------------------- | ------------------- | ---------------------------- |
| Maximum 2 children | Yes                    | Yes                 | Yes                          |
| Ordering           | None                   | Left < Root < Right | Parent follows heap property |
| Complete required  | No                     | No                  | Yes                          |
| Inorder sorted     | No                     | Yes                 | No                           |
| Main purpose       | Hierarchical structure | Searching           | Priority                     |
| Typical structure  | General                | Ordered             | Complete                     |

---

Don't memorize isolated definitions. Remember this:

                    DATA
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
      Sequential             Hierarchical
          │                       │
    Array / Linked List          Tree
                                  │
                            At most 2 children?
                                  │
                                  ↓
                            Binary Tree
                                  │
                         Need ordered search?
                                  │
                                  ↓
                                BST
                                  │
                         Need guaranteed height?
                                  │
                                  ↓
                       Balanced BST
                       /           \
                     AVL       Red-Black

And the fundamental tradeoff:

UNSORTED ARRAY
Search       O(N)
Insert       O(1)*
Delete       O(N)

SORTED ARRAY
Search       O(log N)
Insert       O(N)
Delete       O(N)

BALANCED BST
Search       O(log N)
Insert       O(log N)
Delete       O(log N)

HASH TABLE
Search       O(1) average
Insert       O(1) average
Delete       O(1) average
BUT → no natural ordering

That is why BST exists.

# 27. BST vs Binary Heap

### BST

```text
Left < Root < Right
```

Useful for:

```text
Searching
Ordered data
Finding predecessor/successor
```

### Min Heap

```text
Parent <= children
```

Useful for:

```text
Minimum element
Priority Queue
Heap operations
```

### Max Heap

```text
Parent >= children
```

Useful for:

```text
Maximum element
Priority Queue
```

Do not confuse:

```text
BST ≠ Heap
```

# 29. Lowest Common Ancestor — Concept

Given two nodes, the **Lowest Common Ancestor (LCA)** is the lowest node that is an ancestor of both.

Example:

```text
        1
       / \
      2   3
     / \
    4   5
```

LCA of:

```text
4 and 5
```

is:

```text
2
```

LCA of:

```text
4 and 3
```

is:

```text
1
```

For a BST, LCA can exploit the ordering property.

This is **medium priority**, not something to spend hours on for EY.

5. Likely Verbal Follow-Ups (be ready to answer in plain English)
Question	Answer in one line
Why does inorder give sorted order?	Because left < root < right is enforced at every node, and inorder visits left, then root, then right.
What happens if you insert sorted data into a BST?	It degenerates into a skewed tree (like a linked list) — height O(n) instead of O(log n).
How do self-balancing trees fix this?	AVL trees do rotations to keep left/right height difference ≤1 after every insert/delete; Red-Black trees use color rules to bound height at O(log n).
Recursion vs iteration for traversal?	Recursion uses the implicit call stack (simpler code); iterative versions use an explicit stack and avoid stack-overflow risk on very deep trees.
BST vs Hash Map — when would you pick a BST?	When you need sorted order, range queries, or "k-th smallest" — a hash map gives O(1) lookup but no ordering.
Where are trees used in real systems?	Database indexes (B-trees / B+ trees), file systems, autocomplete (tries), decision trees in ML. Tie this to your MongoDB/SQL project experience if asked.
Time complexity of BST operations?	O(h) where h = height; O(log n) balanced, O(n) worst case (skewed).
Space complexity of recursive traversal?	O(h) due to the call stack — O(log n) balanced, O(n) skewed.
