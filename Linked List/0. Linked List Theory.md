# Linked List — EY Placement Theory

> **Goal:** Understand why Linked Lists exist, when to use them, their trade-offs, types, and time/space complexities.
>
> **EY Focus:** Fundamentals + standard operations. Do not waste time on obscure linked-list variations.

---

# 1. What is a Linked List?

A **Linked List** is a linear data structure made up of **nodes**, where each node stores:

1. Data
2. A pointer/reference to another node

For a **Singly Linked List**:

```text
[data | next]
```

Example:

```text
HEAD
 ↓
[10 | •] → [20 | •] → [30 | NULL]
```

The `head` pointer stores the address of the first node.

The last node points to `NULL`.

---

# 2. Why Do We Need Linked Lists?

The main problem with arrays is that their elements are stored in **contiguous memory**.

Example:

```text
Array:

[10][20][30][40][50]
```

Suppose we want to insert `25` between `20` and `30`.

```text
[10][20][25][30][40][50]
```

Elements after the insertion position may need to be shifted:

```text
30 → right
40 → right
50 → right
```

Therefore insertion can take:

```text
O(n)
```

A Linked List handles this using pointers.

Before:

```text
10 → 20 → 30 → 40
```

After inserting `25`:

```text
10 → 20 → 25 → 30 → 40
```

Only the relevant links need to be changed.

If the insertion node/position is already known:

```text
O(1)
```

---

# 3. Core Idea

Do NOT think:

> "Linked List = dynamic array"

Think:

> **Linked List = nodes connected through pointers**

Array:

```text
[10][20][30][40]
```

Linked List:

```text
10 → 20 → 30 → 40
```

The nodes of a Linked List do **not** need to be adjacent in physical memory.

Example:

```text
Memory:

0x100 → [10 | 0x500]

0x500 → [20 | 0x220]

0x220 → [30 | NULL]
```

The pointers create the logical sequence.

---

# 4. Node Structure

A singly linked-list node contains:

```text
[data | next]
```

In C++:

```cpp
struct Node {
    int data;
    Node* next;
};
```

Example:

```text
Node 1
┌──────┬──────┐
│  10  │  •───┼──────┐
└──────┴──────┘      ↓
                   Node 2
                 ┌──────┬──────┐
                 │  20  │  •───┼──────┐
                 └──────┴──────┘      ↓
                                    Node 3
                                  ┌──────┬──────┐
                                  │  30  │ NULL │
                                  └──────┴──────┘
```

---

# 5. Why Not Always Use Linked Lists?

Linked Lists are NOT universally better than arrays.

They solve a different problem.

## Main disadvantages

### 1. No Random Access

Array:

```cpp
arr[500]
```

Time:

```text
O(1)
```

Linked List:

```text
HEAD → 1 → 2 → 3 → ... → 500
```

To reach node 500, we must traverse the list.

Time:

```text
O(n)
```

---

### 2. Extra Memory

Array:

```text
[data]
```

Linked List:

```text
[data | next]
```

Every node requires pointer storage.

Doubly Linked List:

```text
[prev | data | next]
```

requires even more memory.

---

### 3. Poorer Cache Locality

Arrays store elements next to each other in memory.

```text
[10][20][30][40][50]
```

This is cache-friendly.

Linked-list nodes can be scattered:

```text
Node A → Node C → Node B → Node D
```

The logical order is maintained through pointers, not physical memory layout.

Therefore Linked Lists generally have poorer cache locality.

---

# 6. When Should We Use a Linked List?

Use a Linked List when:

* Frequent insertion/deletion is required
* Random access is not important
* Sequential traversal is sufficient
* The size changes dynamically
* You already have a pointer/reference to the relevant node
* You want to avoid shifting many elements

Typical idea:

```text
Frequent modifications
        ↓
Linked List can be useful
```

---

# 7. When Should We Prefer an Array / Vector?

Use an Array or Vector when:

* Random access is important
* You frequently need `arr[i]`
* Most operations are reads/accesses
* Cache performance matters
* Insertions/deletions are relatively rare

Example:

```cpp
arr[1000]
```

Array:

```text
O(1)
```

Linked List:

```text
O(n)
```

---

# 8. Array vs Linked List

| Feature                 |  Array / Vector |          Linked List |
| ----------------------- | --------------: | -------------------: |
| Memory layout           |      Contiguous |       Non-contiguous |
| Random access           |        **O(1)** |             **O(n)** |
| Search                  |            O(n) |                 O(n) |
| Insert at beginning     |            O(n) |             **O(1)** |
| Delete at beginning     |            O(n) |             **O(1)** |
| Insert after known node |            O(n) |             **O(1)** |
| Delete known node       |            O(n) |            **O(1)*** |
| Extra pointer memory    |              No |                  Yes |
| Cache locality          |            Good |     Generally poorer |
| Dynamic growth          | Vector can grow | Naturally node-based |
| Indexing                |             Yes |                   No |

> *For linked-list deletion, this assumes the relevant node/position is already known. Finding it can take `O(n)`.

---

# 9. Important Complexity Trap

Do NOT blindly say:

> "Insertion in Linked List is O(1)."

That is incomplete.

Correct:

> **Insertion is O(1) when the insertion position/node is already known.**

If we first need to search for the position:

```text
Search position → O(n)
Insertion        → O(1)

Total             → O(n)
```

Example:

```text
10 → 20 → 30 → 40
```

If we already have a pointer to `20`:

```text
10 → 20 → 30
```

Insert `25`:

```text
10 → 20 → 25 → 30
```

Pointer changes:

```text
25->next = 20->next
20->next = 25
```

Insertion:

```text
O(1)
```

# 10. Types of Linked Lists

There are four important types to know.

---

# 10.1 Singly Linked List

Each node contains:

```text
[data | next]
```

Example:

```text
10 → 20 → 30 → NULL
```

Traversal:

```text
Forward →
```

Advantages:

* Simple
* Less memory than DLL
* Easy to implement

Disadvantage:

* Cannot directly move backward

---

# 10.2 Doubly Linked List

Each node contains:

```text
[prev | data | next]
```

Example:

```text
NULL ← 10 ⇄ 20 ⇄ 30 → NULL
```

Can traverse:

```text
Forward →
Backward ←
```

### Advantages

* Can move in both directions
* Deletion can be easier when the node is already known
* Useful when both forward and backward traversal are needed

### Disadvantages

* Extra memory for `prev`
* More pointer manipulation
* More chances of pointer errors

---

# 10.3 Circular Singly Linked List

The last node points back to the first node.

Normal:

```text
10 → 20 → 30 → NULL
```

Circular:

```text
      ┌──────────────┐
      ↓              │
10 → 20 → 30 ────────┘
```

So:

```text
30->next = 10
```

There is no `NULL` at the end.

Useful when the structure naturally repeats.

Example:

```text
Round-robin scheduling
```

---

# 10.4 Circular Doubly Linked List

Combines:

* Doubly linked list
* Circular structure

Example:

```text
       ┌──────────────────┐
       ↓                  │
10 ⇄ 20 ⇄ 30 ⇄ 40
↑                     ↓
└─────────────────────┘
```

Each node has:

```text
prev
data
next
```

For a circular list:

```text
head->prev = tail
tail->next = head
```

For EY:

> Know the concept. Do not spend significant coding time on it.

---

# 11. Linked List Complexity

## Singly Linked List

| Operation                           |     Time |
| ----------------------------------- | -------: |
| Access kth element                  | **O(n)** |
| Search                              | **O(n)** |
| Insert at head                      | **O(1)** |
| Delete head                         | **O(1)** |
| Insert after known node             | **O(1)** |
| Delete after known node             | **O(1)** |
| Insert at tail without tail pointer |     O(n) |
| Insert at tail with tail pointer    | **O(1)** |
| Delete tail                         | **O(n)** |

Why is delete tail `O(n)` in a singly linked list?

Because to delete the last node, we need the **previous node**.

```text
10 → 20 → 30 → NULL
          ↑
         tail
```

We must find:

```text
20
```

before changing:

```text
20->next = NULL
```

So we need traversal.

---

# 12. Why Is Head Insertion O(1)?

Current:

```text
HEAD
 ↓
10 → 20 → 30
```

Create:

```text
5
```

Set:

```text
5->next = head
head = 5
```

Result:

```text
HEAD
 ↓
5 → 10 → 20 → 30
```

Only two pointer operations.

Therefore:

```text
O(1)
```

---

# 13. Why Is Array Insertion Different?

Array:

```text
[10][20][30][40]
```

Insert `5` at beginning:

```text
[5][10][20][30][40]
```

Existing elements have to move.

```text
40 → right
30 → right
20 → right
10 → right
```

Therefore:

```text
O(n)
```

Linked List:

```text
5 → 10 → 20 → 30 → 40
```

No shifting.

If head is known:

```text
O(1)
```

---

# 14. Why Is Linked List Access O(n)?

Suppose:

```text
HEAD
 ↓
10 → 20 → 30 → 40 → 50
```

Want element `40`.

We cannot do:

```cpp
head[3]
```

There is no indexing.

We must traverse:

```text
10
 ↓
20
 ↓
30
 ↓
40
```

Therefore:

```text
O(n)
```

---

# 15. Head and Tail

A Linked List normally starts with:

```text
head
```

Example:

```text
head
 ↓
10 → 20 → 30 → NULL
```

We can also maintain:

```text
head
tail
```

Example:

```text
head                 tail
 ↓                     ↓
10 → 20 → 30 → 40 → NULL
```

Maintaining a `tail` pointer allows insertion at the end in:

```text
O(1)
```

for a singly linked list.

---

# 16. Linked List vs Vector — Practical C++ Point

In C++, `vector` is usually preferable to a linked list when you need a general-purpose sequence.

Why?

`vector` provides:

```text
O(1) random access
```

and excellent cache locality.

A Linked List should be chosen because its **pointer-based insertion/deletion characteristics** are useful, not simply because it can grow dynamically.

# 17. Real-World Applications

Linked Lists can be useful for:

### 1. Implementing stacks

```text
push → head
pop  → head
```

Both:

```text
O(1)
```

### 2. Implementing queues

Maintain:

```text
head + tail
```

### 3. Browser history

A doubly linked structure can represent:

```text
Page A ⇄ Page B ⇄ Page C
```

with movement in both directions.

### 4. Round-robin systems

Circular linked lists can model:

```text
A → B → C → D
↑           ↓
└───────────┘
```

# 21. The Key Trade-Off

The entire topic can be summarized as:

```text
ARRAY / VECTOR

Fast access
    ↓
O(1) indexing

But

Insertion / deletion in middle
    ↓
May require shifting
    ↓
O(n)
```

versus:

```text
LINKED LIST

No fast indexing
    ↓
O(n) access

But

Pointer-based insertion/deletion
    ↓
Can be O(1)
when position/node is known
```

---

# 22. Interview Answer — Why Linked List?

If asked:

> **"Why would you use a Linked List instead of an Array?"**

Answer:

> A linked list is useful when frequent insertion and deletion are required and random access is not important. Unlike an array, its nodes do not need contiguous memory, and insertion or deletion can be performed in O(1) when the relevant node or position is already known. The trade-off is O(n) access time, additional pointer memory, and generally poorer cache locality.

---

# 23. Interview Answer — Why Not Always Linked List?

> A linked list does not support O(1) random access. Accessing the kth element requires traversal, which takes O(n). It also requires extra memory for pointers and generally has worse cache locality than an array or vector. Therefore, the choice depends on the required operations.
