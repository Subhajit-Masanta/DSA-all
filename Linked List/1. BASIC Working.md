# Linked List Foundation - Why `Node* next` Instead of `Node next`

## Prerequisites

Before learning Linked Lists, understand:

* Class = Blueprint
* Object = Real instance created from blueprint
* Pointer = Variable that stores an address

---

# 1. What is a Node?

A Linked List is made up of many **Nodes**.

Each Node stores:

1. Data
2. Information about where the next Node is

Example:

```text
10 -> 20 -> 30 -> NULL
```

One Node looks like:

```cpp
class Node
{
public:
    int data;
    Node* next;
};
```

---

# 2. Why Do We Need a Class?

Suppose we only have:

```cpp
int x = 10;
```

An integer can store only one value.

But a Linked List node must store:

```text
data = 10
next = address of another node
```

One variable cannot store both.

So we create our own data type.

```cpp
class Node
{
public:
    int data;
    Node* next;
};
```

Think:

```text
int      -> built-in type
double   -> built-in type
Node     -> user-defined type
```

---

# 3. Class vs Object

Class:

```cpp
class Node
{
public:
    int data;
    Node* next;
};
```

creates **nothing**.

It is only a blueprint.

Example:

```cpp
Node n;
```

Now an actual object is created.

Memory:

```text
+----------------+
| data           |
+----------------+
| next           |
+----------------+
```

---

# 4. Understanding `Node* next`

Read this as:

```text
next is a pointer to a Node
```

NOT

```text
next is a Node
```

---

Example:

```cpp
Node A;
Node B;
```

Suppose:

```cpp
A.next = &B;
```

Memory:

```text
A

data = 10
next = address of B

          |

          v

B

data = 20
next = NULL
```

This creates:

```text
A ---> B
```

---

# 5. Why NOT `Node next`?

Many beginners think this should work:

```cpp
class Node
{
public:
    int data;
    Node next;
};
```

It does NOT.

---

## Compiler Thinking

Compiler asks:

> "How much memory does one Node need?"

It sees:

```text
Node contains:

int data
Node next
```

To calculate Node size,

it first needs to know the size of another Node.

But that Node also contains another Node.

Which contains another Node.

Which contains another Node.

Forever.

Visualization:

```text
Node

|
+--Node

    |
    +--Node

        |
        +--Node

            |
            +--Node

                ...
```

Compiler never reaches an end.

This is called:

```text
Infinite Self Reference
```

or

```text
Infinite Recursion
```

Compilation fails.

---

# 6. Why Does Pointer Solve This?

Now write:

```cpp
class Node
{
public:
    int data;
    Node* next;
};
```

Compiler calculates:

```text
int data   -> 4 bytes
Node* next -> 8 bytes (64-bit system)

Total size = fixed
```

Pointer does NOT contain another Node.

It only stores an address.

Example:

```text
5000
```

which means

> "The next node is located at address 5000."

---

# 7. Biggest Misconception

Wrong thinking:

```text
Node

contains

Node

contains

Node

contains

Node
```

Correct thinking:

```text
Node

contains

int data

pointer (address)

actual next Node lives somewhere else
```

---

# 8. Real Memory Visualization

Suppose:

```cpp
Node* head = new Node(10);
head->next = new Node(20);
```

Memory:

```text
Stack

head
 |
 | stores 1000
 |
 v

Heap

Address 1000

+----------------+
| data = 10      |
| next = 5000    |
+----------------+

Address 5000

+----------------+
| data = 20      |
| next = NULL    |
+----------------+
```

Notice carefully:

First node does NOT contain the second node.

It only stores:

```text
5000
```

which is the address of the second node.

---

# 9. Why Use `->` ?

Suppose:

```cpp
Node* ptr;
```

ptr stores:

```text
1000
```

To access data,

compiler first goes to address 1000 and then accesses the member.

Written as:

```cpp
(*ptr).data
```

Shortcut:

```cpp
ptr->data
```

Both are exactly the same.

```cpp
ptr->data == (*ptr).data
```

---

# 10. Constructor Version

Without constructor:

```cpp
Node* node = new Node;

node->data = 10;
node->next = NULL;
```

Three operations.

With constructor:

```cpp
class Node
{
public:
    int data;
    Node* next;

    Node(int val)
    {
        data = val;
        next = NULL;
    }
};
```

Now:

```cpp
Node* node = new Node(10);
```

automatically initializes:

```text
data = 10
next = NULL
```

Cleaner and safer.

---

# 11. Why `head` Is a Pointer

```cpp
Node* head;
```

Read:

```text
head is a pointer to the first Node.
```

Example:

```text
head
 |
 v

10 -> 20 -> 30 -> NULL
```

If head is lost,

the entire linked list becomes unreachable.

---

# 12. Interview One-Liners

### What is a Node?

A Node is a user-defined object that stores data and the address of the next node.

---

### Why `Node* next` instead of `Node next`?

`Node next` would require every Node to contain another complete Node forever, resulting in infinite size.

`Node* next` stores only an address (fixed size), making linked lists possible.

---

### What does `Node* next` actually store?

It stores the **memory address of the next Node**, not the Node itself.

---

### Golden Rule

```text
Node next
↓

Store complete object

(Not possible)

---------------------------------

Node* next
↓

Store only address

(Works perfectly)
```

---

# Memory Trick

Always visualize every linked list like this:

```text
head
 |
 | stores address
 |
 v

+----------------+
| data = 10      |
| next = 5000 ---+------+
+----------------+      |
                         |
                         v

+----------------+
| data = 20      |
| next = 8000 ---+------+
+----------------+      |
                         |
                         v

+----------------+
| data = 30      |
| next = NULL    |
+----------------+
```

Never imagine one Node physically containing another Node.

Each Node lives independently in memory and is connected only through stored addresses.
